# RM9 | Which history should choose next week's momentum settings?

All three portfolios trade the same family of long-only, intraday breakouts. They differ in one decision: when looking at the **same backtested candidates**, which past days should count most? The result is a comparison of **weekly selection methods**, not a search for a universally best ticker or proof that momentum is profitable.

## One actual weekend in the full study

The sealed archive covers **November 14, 2016 to November 13, 2026**: 522 NYSE weeks with 2,514 sessions. Earlier data only warms indicators, screens stocks and measures execution costs. All dates refer to New York exchange sessions, including shortened sessions.

| Role | First decision, made after Friday February 8, 2019 | What uses it |
|---|---|---|
| Search | Nov 14, 2016–Nov 9, 2018 (104 weeks) | Discover candidates and measure their historical **daily** net portfolio returns. |
| Validation | Nov 12, 2018–Feb 8, 2019 (13 weeks) | Apply the same recent, unweighted performance and activity checks to each policy's finalists. |
| Forward test | Feb 11–15, 2019 (one week) | Freeze three choices first; then replay each using the prices actually available that week. |

The next weekend the search **starts on the same date and ends one week later**, validation slides forward one week, and a different forward week becomes available. The 13 weeks are a recent check, not the entire history from which “similar markets” are found. There are **405** forward weeks. The last **52** (Nov 17, 2025 through Nov 13, 2026) are the primary comparison; the preceding 353 are reported separately. Once a forward week ends, its data can enter the next weekend's recent validation window and, 13 weeks later, search. The rule can update; the experimenter cannot adjust the rule after inspecting the primary period and still claim an untouched test. There is no independent held-out-stock claim; the holdout is chronological.

## From a stock to a candidate to a portfolio

1. **Select the weekly trading pool.** Start from dated identities, not a list of today's winners. Use 60 preceding complete sessions of raw closes and dollar volumes, and split-adjusted closes for volatility. Median close ≥ $5, median daily dollar volume ≥ $10M. Split the qualifying candidates into liquidity thirds and volatility thirds within each. Round-robin across the nine cells using seeded stable-ID order, testing for ≥90% observed minute coverage over the preceding 20 sessions. Target **1,000 per week**, without requiring any stock to have ten years of history. Freeze the names for the week and report unfilled places. Delisted names can appear in their historical weeks. Use the market directory fallback only with its documented survivorship limitation.
2. **Build minute signals once.** A completed minute may trigger an order for the next minute. Breakout is mandatory. A candidate adds **one to three** of EMA trend, relative volume, VWAP band and directional ADX, with a particular setting for each. All active components must pass. The inherited grid has 14 subsets and 69,732 legal configurations. Once ready, the engine stores 63 individual Boolean component/setting series as bits; candidate intersections share them. The five components are not five independently competed portfolios.
3. **Discover promising configurations.** Start by sampling across subsets. After actual backtests exist, use the highest neutral (equal-day) scores as parents, exchange settings between parents, occasionally change a filter or move a parameter to a neighboring grid value. A small ensemble of histogram gradient-boosting regressors predicts which **configurations** merit another actual backtest, using their settings and already measured scores. Rank proposals by predicted mean + 0.5 × disagreement; reserve about 20% of nominations for random exploration. The full ensemble uses five regressors, up to 60 boosting iterations each. These are predeclared engineering choices, not tuned market discoveries. The model never predicts a fill or substitutes an estimated return for a backtest.
4. **Measure each nominee before ranking.** Replay it against the historical weekly memberships. The common reference account resets to $100,000 each day so that every candidate's daily path is comparable; it still obeys slot, cash, liquidity, entry, exit and cost limits. Store the actual daily net path and trade counts. For established candidates, add only missing weeks. New candidates must earn their entire earlier history, including recent validation. Keep settings, origins, cohorts, seed, return paths and completed decisions; deterministic refits reconstruct the surrogate as history changes. A standalone serialized model is not needed to resume.
5. **Apply the three weight rules to the older search path.** Uniform: all days equal. Recency: weight halves every 63 calendar days. Similarity: compare the weekend's five-session median stock return, cross-stock dispersion, fraction rising and log median dollar volume with the descriptors known before each older historical week. Scale by historical interquartile ranges, use a Gaussian distance, mix in 20% uniform weight and widen the bandwidth until effective sample size is at least 60% of the historical days. All three score the same returns as weighted mean / weighted standard deviation × √252. Weights change **which candidate looks good**, never what a historical fill earned.
6. **Use a common, recent validation test.** Take each rule's top eight search finalists. On the same preceding unweighted 13 weeks require ≥40 return observations, effective sample size ≥20, ≥10% nonzero-return days, ≥20 round trips, nonnegative compounded return and drawdown ≤20%. Among passes choose highest validation score (stable configuration ID breaks ties); no pass means cash. A program or data error is never counted as cash. Validation is a selection step, not an advertised return.
7. **Run the next week once for all three.** Keep settings fixed; indicators still update each minute. Each policy has its own funded account, carrying equity across days and weekends. Repeat each funded selection with doubled modeled execution costs as a stress scenario; this can change fills and trade counts. No candidate sees that week's outcome before the three choices have been made. Export the exact weekly universe, configuration or reason for cash, evidence, cutoff and account contract.
8. **Read the primary results.** Results include daily net returns, gross returns on the same trades, compound return, drawdown, costs in dollars, trades, inactivity, concentration, rejected signals and cost stress. Compare recency minus uniform and similarity minus uniform on the **same dates**. The bootstrap resamples consecutive 5- or 10-session blocks so neighboring days stay together; 2,000 draws, 97.5% intervals per comparison (two comparisons against uniform). A simple screen flags a method only if both block lengths have a positive lower bound. A null result is useful. Two flagged methods do not establish which beats the other. A favorable relative difference can still mean all three **lost money**. Inspect net, stress, drawdown, activity and concentration before even considering a separate paper demonstration.

## What the machine may change

The machine may select a worker count and candidate budgets **before** seeing forward results. It may not silently shrink the 1,000-stock target, decade, grid, three policies, costs, exit rules or weekend frequency. Warm up the compiled account on three initial-search weeks. Time 16 real configurations at allowed thread counts, feature preparation, a sample surrogate refit, storage reads and durable SQLite writes on the actual filesystem. Use the slowest sampled week per worker choice, a 1.35 timing margin, memory and free-space checks. The closed workload ladder is 24–3,072 initial evaluations and 1–32 new ones per later weekend (powers of two within each ladder). Prefer the highest feasible weekly budget, then the initial budget. These are scoping bounds, not statistically optimal numbers. A single scientific seed is shared across policies; robustness across other seeds is a separate study.

The 48 hours are **cumulative active elapsed compute**, not 48 hours each weekend, not CPU-core-hours and not a promise. Acquisition and queue waits are outside the clock. Admission forecasts allocate 40% initial search, 50% recurring work, 10% preparation and overhead. Those fractions are planning gates; the hard runtime stop is the total. Every subsequent weekend gets the same **number of new candidates** and identical rules; time per weekend can grow. With 405 decisions and budgets I and K, there are I + 404K actual candidates and (I + 404K) × 521 cached reference configuration-weeks. Even the smallest full budget is 222,988 reference replays. The largest is 8,336,000, plus up to six funded replays per forward week. Do not pick budgets based on returns. A partial run or NO_FIT is an engineering result, not a completed policy comparison.

## Reuse

The same code and sealed inputs produce a weekly settings file; Juan's platform must implement its execution contract and demonstrate independent ledger agreement. The last file in this study activates for **Nov 9–13, 2026**; it is not a buy list for a later week. A later live weekend requires fresh, authorized data through its own cutoff, a newly selected config and the platform adapter. The research program deliberately does not place orders. Keep the primary comparison, code hash, raw inventory and configuration if doing a separate longer study.
