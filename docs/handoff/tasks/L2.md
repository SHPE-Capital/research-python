# L2: Exit-policy label as a thin wrapper over T1

| Wave | Level | Depends on | Blocks | Agent |
|---|---|---|---|---|
| 2 | Int | T1, C1c (`triple_barrier`) | R1 and R2 labels, W4 | `strategy-builder` (review: `platform-parity`) |

L2 is superseded in part by [T1](T1.md). The simulator, fill rules and
`ExitPolicy` moved to `trade/` (see the migration table in
[design/architecture.md](../../design/architecture.md)). What remains of L2
is the backward-compatible label module and the five-session reconciliation
with the platform that the original stub asked for.

## Goal

Keep `labels/exit_policy.py` importable for existing code and notebooks, with
no logic of its own, and prove on five real sessions that the research exit
labels match the platform backtest.

Old to new names, applied by the alias and documented in the module docstring:

| Old (L2 stub) | New (T1) |
|---|---|
| `exit_reason = stop` | `stop_loss` |
| `exit_reason = target` | `take_profit` |

The label itself is C1c's `triple_barrier`; L2 adds no label key.

## Behaviour

- The shim contains imports, the alias and a docstring. No fill or exit logic.
- Reconciliation uses the T7 golden layout: each
  `tests/integration/golden/exits/<date>/` holds input bars, a spec with a
  fixed exit policy (stop, target, max hold), the platform ledger exported as
  JSON, and the expected research ledger.
- Sessions: an ordinary session, an open gap through a stop, a bar that
  touches both stop and target, an early close, and a session with missing
  minutes. `session_end` is off, as in every parity run.
- Match tolerances are T7's (`deploy/parity.py`). L2 calls
  `deploy.parity.compare_ledgers`; it does not define its own comparison.
