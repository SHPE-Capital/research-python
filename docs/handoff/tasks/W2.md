## Goal

Compare logistic regression, random forest, LightGBM and an MLP on the same
intraday features, labels and purged walk-forward splits, and show that
model choice matters less than validation and costs.

- `tests/workshop/test_02_intraday_model_comparison.py`

## Interface

`base.yaml` holds data, features (F1, F2, F3, F5), label and `fit_scheme`
(`purged_walk_forward` via C1f, or V1 directly if C1f is not merged). Each
model config overrides `model` only. The notebook prints one table: model,
fold metrics, mean and band (E2 bootstrap when merged), cost-adjusted Sharpe
(E1 when merged).

Stretch exercise (optional, `uv sync --extra nn`): an LSTM using
`sequence_dataset.py`, which turns the feature frame into (window, features)
tensors per symbol without crossing sessions or fold boundaries.

## Behaviour

- Same seed, same splits for every model.
- The LSTM cell is skipped with a message if torch is not installed.
- Expected outcome (hypothesis): on the fixture, tree models and logistic are
  within each other's bootstrap bands.
